# 인원 실적·지출 관리

개인 작업 폴더의 장부를 조회·변경하거나 문서에 집계를 반영할 때 읽는다. 운영 DB·공유 폴더·다른 직원 자료를 자동으로 연결하거나 이관하지 않는다. 초기 장부는 비어 있으며 첫 승인 저장 때 생성된다.

## 조회와 집계

`ledger-query`의 `--program`, `--from`, `--to`, `--kind`를 필요한 만큼 지정한다. 날짜는 실제 업무 날짜 `YYYY-MM-DD`이며 양 끝을 포함한다. `kind`는 `attendance` 또는 `expense`다. 생략하면 두 종류 모두 조회한다. 프로그램명은 같은 프로그램에서 일관되게 사용한다. 미조회 영역은 `null`이며 0으로 표시하지 않는다.

- 연인원은 조회된 회기별 `count`의 합계다. 같은 사람이 여러 회기에 참석하면 매회 포함한다.
- 실인원은 `participantIds`의 중복을 제거한 수다. ID는 작업 폴더 전체에서 한 사람에게 동일하게 사용하는 익명 식별자이며 이름이나 연락처가 아니다. 프로그램별 실인원을 더해 전체 실인원으로 쓰지 않는다.
- 인원수만 알고 ID를 모르면 `participantIds`를 생략한다. 인원이 있는 회기에 ID가 없으면 전체 실인원은 미확정이며 `knownUniqueParticipants`를 전체 실인원으로 대체하지 않는다. ID가 있으면 중복 없이 `count`와 정확히 일치해야 한다.
- 지출은 원화 정수 금액의 합계다. 예산·잔액·목표 달성률·회계 결산 기능으로 확대 해석하지 않는다.

## 등록·정정·삭제

먼저 해당 기간·프로그램을 조회해 기존 기록을 확인한다. 아래 변경 객체를 UTF-8 JSON 파일로 `drafts/`에 저장한 뒤 `ledger-preview --input`에 지정한다. 미리보기는 실제 실적·지출을 변경하지 않는다.

| 필드 | 값 |
|---|---|
| `operation` | `add`, `update`, `delete` |
| `kind` | `attendance`, `expense` |
| `id` | 정정·삭제할 기존 기록의 ID. 등록에는 넣지 않음 |
| `reason` | 정정·삭제 사유. 등록에는 넣지 않음 |
| `data` | 등록·정정 시 전체 내용. 삭제에는 넣지 않음 |

인원 `data`: `program`(프로그램), `date`(실시일), `session`(회기 식별자), `count`(0 이상 정수), 선택 `participantIds`(익명 ID 배열), 선택 `note`(비고). 같은 프로그램·실시일·회기의 중복 등록은 거부된다. 분반을 별도 회기로 관리하면 `session`에 구분을 반영한다.

지출 `data`: `program`, `date`(사용일), `entryKey`(해당 프로그램에서 고유한 지출 식별번호), `item`(항목), `amount`(1원 이상 정수), 선택 `session`·`note`. 증빙번호와 행 구분처럼 같은 지출을 재입력해도 동일하게 재사용할 번호를 사용한다. 번호가 없으면 사용자와 정한 식별번호를 유지하며 매번 새 번호를 만들어 중복 방지를 우회하지 않는다. 환급·취소는 사유를 확인하여 해당 기록을 정정·삭제하고 음수 지출을 입력하지 않는다.

미리보기의 변경 전후·사유·저장 위치를 사용자에게 보여 주고 승인을 확인한다. 삭제는 현재 목록·집계에서 제외하되 이전 값은 변경 이력에 남는다는 점도 보여 준다. 해시는 승인 자체가 아니며 개발 승인·문서 승인으로 실제 장부 쓰기 승인을 대신하지 않는다. 내용이 바뀌면 새 미리보기가 필요하다.

승인 뒤 `ledger-apply --plan <planId> --confirm <confirmHash> --approved`를 실행한다. 호출 뒤 같은 범위를 조회해 반영 결과를 대조한다. 시간 초과·응답 누락 때는 같은 미리보기를 재실행한다. 이미 실행한 요청은 중복 반영하지 않으며 삭제 후 과거 등록 요청도 기록을 부활시키지 않는다. 미리보기 이후 다른 변경이 있으면 다시 조회·미리보기·승인을 진행한다. 잠금 오류 때는 다른 실행의 종료를 확인하며 잠금을 자동 삭제하지 않는다.

## 문서 반영

`ledger-report`에 같은 조회 조건을 전달하면 자료 버전·확인값과 집계 원고를 받는다. 프로그램·기간·조회 종류를 확인한다. `markdown`은 대화 표시용이며, 한글파일은 특수문자 원문을 보존하는 `document` 객체를 JSON으로 직렬화해 새 `drafts/*.json`에 저장한 뒤 `preview --kind create`에 입력한다. 지정 양식에는 확인한 집계 값을 해당 칸에 대응한다. 집계에서 참여자 반응·성과·평가를 추측하지 않는다. 장부가 바뀌면 새 집계를 사용한다. 보고서 파일은 [한글 출력](hangul.md)의 원고→미리보기→승인→생성→검증을 따른다. 집계 조회는 파일 저장이나 장부 변경을 승인하지 않는다.

## 저장·보존

현재 기록·변경 이력은 개인 폴더 `.autosw/ledger.json`, 미리보기는 같은 폴더의 `ledger-plan-*.json`에 저장된다. JSON 평문이며 암호화·공동 편집·자동 백업은 제공하지 않는다. 한 개인 작업 폴더의 로컬 사용만 지원하며 공유 드라이브에서 동시 사용하는 DB가 아니다. 쓰기 중 다른 프로세스는 차단하고 완료 파일만 교체한다. 실패 후 남은 잠금은 실행 중인 프로세스가 없는지 확인한 뒤 수동 복구한다.

정정·삭제 이전 내용과 이미 실행한 요청 ID는 이력에 남는다. 삭제는 개인정보의 완전 파기가 아니다. 이력 일괄 삭제·전체 초기화·다른 자료 이관은 자동 지원하지 않으며 별도의 명시적 요청과 보존 범위 확인이 필요하다. 설치 프로그램 제거·업데이트 때 작업 폴더는 보존한다. 파일 손상·버전 불일치·16MB 한도 초과는 기존 파일을 보존하고 중단한다.
