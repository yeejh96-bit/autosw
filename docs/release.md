# 공개 전 확인

검증된 공개 파일과 설치 방법을 준비하는 단계에 적용합니다. 이 문서는 게시 자체를 승인하지 않습니다.

1. autosw만 복사한 별도 위치에 의존성을 설치하고 `npm run check`를 실행합니다. 상위 프로젝트·운영 자료·기존 전용 런타임 없이 실행돼야 합니다.
   - Node 공식 배포와 winget의 최신 LTS를 확인하고 해당 런타임에서 전체 검사를 수행합니다. 최소 요구 버전을 유지한다면 그 버전도 검사합니다. 직원용 명령은 Node 버전 고정 없이 최신 LTS, autosw는 `@latest`를 사용하며 실제 연결에 저장된 버전은 별도로 확인합니다.
2. 배포 파일 목록에 소스·스킬·공개 예제·필요한 고지만 포함되는지 확인합니다. 개인 작업 폴더·자격 증명·실제 문서·진단 로그·임시 산출물이 들어 있으면 제외합니다.
3. 사용 앱에서 스킬 또는 MCP 지침 조회가 실제로 동작하는지 확인합니다. 정보가 빠진 요청, 기존 초안 수정, 검토만 요청, 지정 양식 출력, 검증 실패를 각각 시험합니다.
4. 실제 한글이 설치된 시험 PC에서 합성 문서의 열기·저장·재열기·PDF 전 페이지 검토와 내용 대조를 수행합니다. 확인한 Windows·한글·앱 버전과 미확인 범위를 기록합니다.
5. 설치·진단·재시작·업데이트·제거가 개인 설정·양식·완성 문서를 보존하는지 확인합니다. 자동 연결 변경은 적용 내용을 먼저 보여 줍니다.
6. 포함 코드와 의존성의 라이선스·저작권·NOTICE를 확인하고 실제 배포 파일에 필요한 고지가 남는지 대조합니다.
7. 공개할 저장소·패키지 이름과 버전, 파일 목록, 지원 범위가 정해진 뒤 사용자의 명시적 배포 요청에 따라 게시합니다. 공개 상태가 불명확하면 중복 게시하지 않고 실제 상태부터 확인합니다.
8. 합성 인원·지출로 미리보기 무변경, 승인 없을 때 차단, 중복·정정·삭제·재시도·동시 쓰기·집계 기준과 문서 반영을 시험합니다. 개인 장부·변경 이력·미리보기가 배포 파일에 들어가지 않는지 확인합니다.

자동 시험 통과, 실제 한글 검증, 직원 사용 시험, 외부 공개 상태를 각각 구분해 기록합니다. 수행하지 않은 단계를 완료로 표시하지 않습니다.
