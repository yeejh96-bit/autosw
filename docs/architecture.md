# 프로젝트 구조와 출처

autosw는 로컬 my-system의 문서 작성·한글 출력을 분리하고 개인별 인원 실적·지출 관리를 추가한 초기판입니다. 원본 프로젝트를 호출하지 않으며 기존 운영 장부·일정·위키·일지·백업 연결을 포함하지 않습니다.

## 역할

| 구성 | 역할 |
|---|---|
| `AGENTS.md` | autosw를 개발하는 AI의 작업 범위와 검증 기준 |
| `skills/autosw-document/` | 직원의 문서 작성·검토·출력 절차와 종류별 지침의 정본 |
| `bin/`·`src/` | 명령행, 작업 폴더 경계, 미리보기와 실행 |
| `src/ledger.mjs` | 인원·지출 검증, 로컬 JSON 저장·변경 이력, 기간·프로그램 집계와 문서 원고 |
| `engine/` | HWPX 구조 읽기·생성·양식 작성·대조와 한글 검증 |
| `vendor/` | 필요한 외부 렌더 코드와 고지 |
| `examples/`·`tests/` | 합성 원고와 재현 시험 |
| `.agents/plugins/marketplace.json` | GitHub에서 추가하는 Codex 플러그인 카탈로그 |
| `plugin.json`·`scripts/install.ps1` | GitHub 플러그인 구성과 첫 사용 준비 |

문서 작성 판단은 스킬이 담당하고, 파일 보호·입력 일치·허용 경로 같은 조건은 실행 도구도 검사합니다. Codex는 설치된 스킬을 따라 플러그인의 명령행을 Windows PowerShell에서 직접 실행합니다.

## 분리한 내용

장부는 별도 개인 작업 폴더에서 빈 상태로 시작합니다. 명령행은 service/ledger 코드를 호출하고, 미리보기는 변경 전후와 현재 장부 해시를 고정합니다. 승인 후 파일 잠금 안에서 원본 변경 여부를 다시 확인하고 현재 기록·변경 이력·재실행 식별자를 하나의 JSON에 원자적으로 저장합니다. 집계는 한 번 읽은 자료 버전에서 계산하며 문서 원고에도 조회 조건과 버전을 표시합니다. 저장과 입력 계약의 정본은 [인원·지출 관리](../skills/autosw-document/references/ledger.md)입니다.

문서 준비·초안·검토·한글 출력 규칙을 범용화했습니다. 문체 기준은 계획·결과·회의·기타 문서로 나누고 기관의 고정 명칭·사업목적·결재선·자료지도 연결을 제거했습니다. 기관 양식과 이전 문서는 사용자가 지정한 작업 폴더에서만 입력받습니다.

한글 처리 코드의 실제 복사 범위와 의존성은 `engine/`·`vendor/`의 파일과 고지를 따릅니다. 구조 읽기와 후보 파일 대조를 실제 한글 검증과 구분하는 기존 기준을 유지합니다.

## 원본 프로젝트와의 관계

물리적으로 다른 프로젝트의 하위 폴더에 둘 수 있지만, 실행과 배포 범위는 autosw 폴더입니다. 부모 프로젝트의 설정·업무 자료·변경 이력을 공개판에 포함하지 않습니다. 부모 프로젝트 안에서 우연히 찾은 의존성에 기대지 않는지는 별도 위치에 설치한 시험으로 확인합니다.

GitHub에서 플러그인과 소스를 배포합니다. 첫 설정에서 사용자 계정의 autosw 전용 실행 환경을 준비하며 업무 폴더는 분리합니다. 사용자 업무 폴더는 각 명령에 전체 경로로 전달합니다.
