# 프로젝트 구조와 출처

autosw는 로컬 my-system의 문서 작성·한글 출력을 분리하고 개인별 인원 실적·지출 관리를 추가한 초기판입니다. 원본 프로젝트를 호출하지 않으며 기존 운영 장부·일정·위키·일지·백업 연결을 포함하지 않습니다.

## 역할

| 구성 | 역할 |
|---|---|
| `AGENTS.md` | autosw를 개발하는 AI의 작업 범위와 검증 기준 |
| `skills/autosw-document/` | 직원의 문서 작성·검토·출력 절차와 종류별 지침의 정본 |
| `bin/`·`src/` | 명령행·MCP, 작업 폴더 경계, 미리보기와 실행 연결 |
| `src/ledger.mjs` | 인원·지출 검증, 로컬 JSON 저장·변경 이력, 기간·프로그램 집계와 문서 원고 |
| `engine/` | HWPX 구조 읽기·생성·양식 작성·대조와 한글 검증 |
| `vendor/` | 필요한 외부 렌더 코드와 고지 |
| `examples/`·`tests/` | 합성 원고와 재현 시험 |
| `.agents/plugins/marketplace.json` | GitHub에서 추가하는 Codex 플러그인 카탈로그 |
| `plugin.json`·`mcp.json` | 배포 지침과 고정 버전 npm 실행 패키지를 연결하는 플러그인 구성 |

문서 작성 판단은 스킬이 담당하고, 파일 보호·입력 일치·허용 경로 같은 조건은 실행 도구도 검사합니다. MCP는 사용 순서의 짧은 안내와 도구를 제공하고 상세 작성 기준은 같은 스킬 자료를 조회합니다. 작성 지침을 연결 방식마다 따로 수정하지 않습니다.

## 분리한 내용

장부는 별도 개인 작업 폴더에서 빈 상태로 시작합니다. CLI와 MCP가 같은 service/ledger 코드를 호출하고, 미리보기는 변경 전후와 현재 장부 해시를 고정합니다. 승인 후 파일 잠금 안에서 원본 변경 여부를 다시 확인하고 현재 기록·변경 이력·재실행 식별자를 하나의 JSON에 원자적으로 저장합니다. 집계는 한 번 읽은 자료 버전에서 계산하며 문서 원고에도 조회 조건과 버전을 표시합니다. 저장과 입력 계약의 정본은 [인원·지출 관리](../skills/autosw-document/references/ledger.md)입니다.

문서 준비·초안·검토·한글 출력 규칙을 범용화했습니다. 문체 기준은 계획·결과·회의·기타 문서로 나누고 기관의 고정 명칭·사업목적·결재선·자료지도 연결을 제거했습니다. 기관 양식과 이전 문서는 사용자가 지정한 작업 폴더에서만 입력받습니다.

한글 처리 코드의 실제 복사 범위와 의존성은 `engine/`·`vendor/`의 파일과 고지를 따릅니다. 구조 읽기와 후보 파일 대조를 실제 한글 검증과 구분하는 기존 기준을 유지합니다.

## 원본 프로젝트와의 관계

물리적으로 다른 프로젝트의 하위 폴더에 둘 수 있지만, 실행과 배포 범위는 autosw 폴더입니다. 부모 프로젝트의 설정·업무 자료·변경 이력을 공개판에 포함하지 않습니다. 부모 프로젝트 안에서 우연히 찾은 의존성에 기대지 않는지는 별도 위치에 설치한 시험으로 확인합니다.

GitHub에는 이 프로젝트의 소스를, npm에는 실행 패키지를 배포합니다. 새 버전의 커밋·push·npm 게시도 명시적으로 승인된 배포 작업에서 수행합니다. 원본 프로젝트와 개인 작업 폴더는 포함하지 않습니다.

GitHub 플러그인은 저장소의 작성 지침과 npm의 고정 버전 MCP를 사용하므로 플러그인 캐시에 의존성을 직접 설치하지 않습니다. Node는 별도 준비하며 기본 개인 작업 폴더를 먼저 초기화합니다. 사용자 지정 폴더에는 프로젝트별 MCP 연결을 사용합니다. 설치 경로별 명령과 지원 범위는 [README](../README.md#설치-방법-선택)에서 관리합니다.
