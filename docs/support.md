# 지원 범위와 문제 해결

## 작성 지침과 파일 처리

계획서·결과보고서·회의록·복명서·설문지 등은 문서 작성 지침의 범위입니다. 지원 목록에 문서 이름이 있다는 사실만으로 그 이름의 모든 한글 양식을 자동 편집할 수 있는 것은 아닙니다. 입력 파일의 구조와 실제 검증 결과로 판단합니다.

- 새 HWPX: 제목, 일반 문단, 한 단계 목록, 병합 없는 직사각형 표, 명시적 쪽 나눔을 지원하는 생성 경로를 사용합니다. 그림·사진·서명·수식·머리말·꼬리말·복잡한 병합·혼합 글자 서식의 새 생성은 지원 대상으로 안내하지 않습니다.
- 기존 HWPX: 문단·표·빈칸의 실제 구조를 읽고 지원되는 위치의 텍스트를 변경합니다. 혼합 서식·부모 표 영역·지원 밖 구조의 변경을 조용히 생략하지 않습니다.
- HWP 입력: 설치된 한글을 통해 HWPX 사본과 PDF로 변환할 수 있습니다. HWP 원문 내용의 자동 대조는 완료되지 않으므로 `hwp-source-needs-review` 상태에서는 완성본 저장이 차단됩니다. 사용자가 원문을 대조한 뒤 변환 HWPX를 새 작성 절차의 입력으로 사용합니다.
- HWP 출력: HWPX 작성·검증 경로에서 `check-hangul --format HWP`로 실제 HWP 사본을 만들 수 있습니다. 재열기 후 내용 대조용 HWPX 사본을 별도로 지정해야 하며, 검토를 마치면 새 HWP 완성본으로 저장합니다. 기존 HWP 파일을 같은 이름으로 자동 수정·교체하는 흐름은 원문 대조 제한 때문에 지원 대상으로 안내하지 않습니다.
- 자체 미리보기: 근사 조판입니다. 생성 성공이나 페이지 수 일치를 실제 한글 배치 일치로 해석하지 않습니다.
- 한글 검증: Windows와 설치된 한글 프로그램을 사용합니다. 자동 변환·재열기·PDF 출력 뒤 전 페이지 검토와 본문 대조가 필요합니다.

지원 범위 밖 요소가 있으면 마지막 완료 단계, 실패 위치, 남은 작업을 알립니다. 사용자가 요청하지 않은 다른 파일 형식이나 외부 서비스로 자동 전환하지 않습니다.

## 인원 실적과 지출

개인 작업 폴더 안에서 회기별 인원, 익명 참여자 ID, 지출 식별번호·항목·원화 정수 금액을 관리합니다. 조회·등록·전체 필드 정정·삭제·기간 및 프로그램 집계·문서 원고를 지원합니다. 조회하지 않은 영역은 미조회로 표시하며, 인원이 있는 회기에 참여자 ID가 없으면 실인원은 미확정입니다. 상세 입력·보존 조건은 [관리 절차](../skills/autosw-document/references/ledger.md)를 따릅니다.

공동 편집 서버·외부 DB·자동 이관·암호화·자동 백업·일정·업무일지·위키는 지원하지 않습니다. 목표·예산·잔액·결의서 결재와 회계 결산도 이번 범위 밖입니다. 등록을 취소해도 변경 이력과 미리보기에 이전 값이 남으므로 개인정보 완전 삭제 기능으로 안내하지 않습니다.

## 연결 환경

MCP는 로컬 프로세스로 실행됩니다. Codex 연결은 설치 미리보기 후 사용자가 지정한 작업 폴더에 적용할 수 있습니다. 이 설정은 전역 설정을 바꾸지 않습니다. 기존 설정·스킬이 있는 폴더는 자동으로 덮어쓰지 않으므로 현재 설정을 확인해 병합해야 합니다. 다른 앱은 해당 앱의 로컬 MCP 지원과 설정 형식을 확인해야 합니다.

npm 배포판의 `setup`은 개인 작업 폴더를 보여 주고 승인 후 버전을 고정한 `npx` MCP 실행을 등록합니다. Node와 npm이 설치되어 있어야 하며 첫 실행이나 캐시 삭제 후에는 npm 접속이 필요할 수 있습니다. npm 설치 경로를 그대로 연결하지 않습니다. `setup --npm --workspace <개인폴더>`는 미리보기, `--apply`를 추가하면 적용합니다. 소스 설치의 기존 `setup --workspace`는 지정된 로컬 설치 경로를 사용하므로 설치 폴더를 옮기면 다시 연결해야 합니다.

직원의 Node 준비·설치 명령·앱 재시작·연결 확인은 [Codex 설치 안내](install-codex.md)를 따릅니다. Node의 최소 지원 범위는 24.22.1 이상 25 미만이며 새 설치와 개발에는 24.22.2를 권장합니다. `.nvmrc`는 개발 버전 기준이고, 이미 설치된 Node를 자동으로 업데이트하지 않습니다. npm의 `setup` 자체도 Node를 설치하지 않습니다. 현재 안내는 Codex 프로젝트에 MCP 설정과 작성 지침을 설치하는 방식이며 별도의 플러그인 마켓 설치 명령은 제공하지 않습니다.

플러그인은 스킬과 연결 정보를 묶는 설치 형식이며, 프로젝트의 `AGENTS.md`가 모든 ChatGPT 대화에 자동 적용되는 것은 아닙니다. 문서 작성 기준은 배포 스킬과 MCP의 지침 조회를 통해 제공합니다. 웹 ChatGPT·모바일에서 로컬 PC 파일에 접근하는 경로는 이 초기판의 직접 설치 범위가 아닙니다.

## 자주 생기는 상태

| 상태 | 처리 |
|---|---|
| Node·PowerShell·브라우저·한글이 없음 | `doctor`의 누락 항목을 확인하고 필요한 기능을 설치·준비한 뒤 재개 |
| 한글 접근 확인창·열기 거절 | 사용자가 직접 허용 여부를 정함. 설정 우회나 일괄 응답을 하지 않음 |
| 파일 잠금·검증 실패 | 원본과 기존 완성본 보존. 실패한 단계만 재개 |
| 미리보기 후 본문·양식 변경 | 새 미리보기로 내용과 저장 위치 재확인 |
| 출력 파일이 이미 있음 | 다른 문서인지 확인. 새 후보 파일로 작업하며 보호 기능을 해제하지 않음 |
| 자기 조판과 실제 한글 배치가 다름 | 실제 한글 PDF에서 확인하고 검증 상태를 분리 |
| 암호·보호·서명·지원 밖 구조 | 실패 이유를 보고하고 지원 범위를 넘는 편집 중단 |

한글 접근 확인창을 기다리는 동안 도구는 PowerShell을 시간 제한으로 강제 종료하지 않습니다. AI 앱이 시간 초과나 취소를 표시해도 한글 작업의 종료를 뜻하지 않으므로 확인창과 출력 파일을 확인한 뒤 재개합니다. 기존 한글 프로세스를 일괄 종료하지 않습니다.

## 데이터와 업데이트

AI에 전달한 본문과 도구 응답은 이용 중인 AI 서비스의 처리 대상이 될 수 있습니다. 실제 개인정보가 있는 문서를 오류 신고나 공개 저장소에 올리지 않습니다. 재현이 필요하면 식별정보 없는 합성 사본을 사용합니다.

기관 양식·설정·원고·완성본은 설치 폴더 밖 작업 폴더에 둡니다. 프로그램 업데이트나 제거 때 작업 폴더를 삭제하지 않습니다. 업데이트 전 사용 버전과 설정을 보관하고 새 버전을 별도 위치에서 시험한 뒤 연결을 바꾸는 방식을 권장합니다.
